## 冻结前的证据

SQ既有数据检查：低档reference端到端P99组中位159.029ms、提交后P99159.028ms、注入等待P990.002367ms；高档分别358.842/255.567/153.996ms。分位数不能相加，也不能仅凭这些边际分位数确定单个尾请求的原因。现有Q/C模型不是完整RDMA延迟或P99模型，不能以预测收益替代实测收益。

## 三组

reference使用冻结原O算法/库；integer使用标定容量比例四舍五入后的固定整数片数（当前类似8:8），不再为了小比例偏差轮换8:8/9:7；gain使用同一初值，加收益门槛和持续确认。

所有新组复用SQ私有库构建机制、48B控制器审计、原152B决定轨迹。只替换原批量门槛以上、两候选、1MiB/16×64KiB、单caller的普通多轨配额。probe100、健康/资格过滤、后台EWMA、实际传输和重试机制不变。新正常权重定义为实际整数配额k/16，不记录一个未执行的连续理想权重。

gain规则（正式前冻结，结果出来后不调参）：

1. 每普通请求累计两个inflight字节观测，20ms非重叠窗口取请求样本均值；这不是时间加权剩余线速工作。空闲>200ms只清空窗口/确认，保留已选择的整数配额。
2. 候选完成时间 T(k)=max((Q0+k*S)/C0 if k>0 else 0, (Q1+(16-k)*S)/C1 if k<16 else 0)。包含端点0/16，允许预测收益足够时避开一侧；不新增人为等待。
3. 用两轨闭式解的floor/ceil、两个端点及当前配额求候选；同等完成时间优先靠近当前配额。每次允许相对当前配额最多移动2片，重新计算这个实际步长的收益，而不是拿未执行目标的收益过门槛。
4. 收益须严格大于 max(0.5*S/min(C0,C1), 0.1*M/(C0+C1))。这是固定工程门槛，不是统计置信区间或真实P99预测。三个连续窗口提出同一个满足收益门槛的整数目标，且距上次调整>=100ms，才执行；执行后清空确认。
5. 每请求只有统计累加/当前配额读取；候选比较每20ms才发生，无逐Slice债务循环、无逐请求17候选枚举。资源/故障不可用路径沿用原实现，不据此宣称恢复验收通过。

- 先用原V2库做S0/S1/D0各3次当天标定（12s+3s预热）。容量参考只用于固定种子；共享单接收NIC意味着C0+C1不是双轨总容量。

- pilot三策略×两档（225/675rps）各8s+1s；全部通过才进入正式。
- 正式三策略×两档×3重复，每次60s+5s；饱和三策略×3重复，每次30s+5s。预先固定随机顺序。输入仍为1.8874368/5.6623104Gbps，不按新标定改变输入以便明确工作负载。
- 测量期间不并发分析/编译；失败保存并停止。有效阶段结束后离线分析。三个重复仅用于初筛，不能声称生产非劣。

## 联合验收

同重复配对原算法后，两档端到端P99比的中位均<=0.90，且每次<=1.05；权重跨度和5pp往返率比的中位均<=0.50，并无持续往返；250ms实际字节份额跨度比中位<=0.50，真正相邻普通决策的配额切换频率不增加。饱和吞吐比中位>=0.98、每次>=0.95；固定输入吞吐跟随和完整到达/完成核验通过。P99窗口CV与吞吐CV另作不恶化检查，不能只展示整体P99改善。

P99以planned-arrival到完成计算，保留排队和drain，另报提交后与注入等待；不剔除最差重复，不把三个分位数相加。原1秒P99窗口的低档样本不足保持N/A；补充统一5秒窗口P99（每窗>=500样本，60s仅12窗）作描述，不冒充满足原20有效窗门槛的验收。
