# CAND：同负载权重候选对照（2026-09-17）

目标：比较原算法与三个低开销候选的真实权重轨迹；不能仅以曲线变平宣称性能优化成功。
所有执行在 SSH 的 mooncake 环境，单主机单会话，数据/库/报告均在仓库外，不使用 scp。

## 四个实验策略

| 策略 | 计算权重 | 整数分片 |
| --- | --- | --- |
| original | 原 inverse-score | 原 floor + 全余数给最大权重 |
| smooth | 原权重经10ms一阶低通，gain=dt/(10ms+dt) | 同原算法 |
| hysteresis | 同smooth；滤波内部状态持续更新，与上次实际权重差≥2pp才发布新权重 | 同原算法 |
| remainder | 完全保留原权重 | floor后将余数给小数余量最大的轨，平局选较小dev ID |

smooth/hysteresis不等待、不延迟提交；变化的是当前调用使用的权重。仍有额外计算与
状态读写，是否增加端到端时延由实测回答。它们会引入控制响应滞后，不能把滞后藏起来。
本轮是单caller/单位置/双轨原型，TLS状态按selector与有序候选设备对区分；候选集变化
或空闲≥100ms立即用当前权重重新初始化，不缓存已不可用设备。完整多线程、GPU位置、
请求优先级及故障恢复泛化未在本轮验收。探测周期100次及其原分配规则保持不变。

原评分、带宽EWMA alpha=.01、NUMA惩罚及边界不改。三个候选分别检验输出平滑、
在平滑上增加滞回、独立整数放大修正；不是同时修改所有项。余数候选虽不直接改权重，
但真实分配改变可能经完成反馈影响后续权重，不能把不同运行的权重视为同一输入回放。

## 测试矩阵

真实A10双eRDMA→erdma_test单eRDMA，Host内存、发送NUMA0，双方6 lanes，
1MiB/request、16×64KiB Slice、每API batch一个request、Q128、单caller。
同O固定计划输入：参考9.6544Gbps的20%/60%，不是硬件利用率。比较实际注入CV。
4策略×2档×3重复，每次60秒+5秒预热，主统计第10–60秒，按固定种子块内打乱。
先每策略做一个8秒60% pilot并核验，再启动正式24点；失败停止并保留，不静默替换。
本轮重新跑同时期original控制，不将旧O某个最佳重复当对照。

## 观测与验收

原始计算权重由捕获的原score重建；实际采用权重从分配器捕获。扩展192字节逐决策
记录还保存滤波前状态/已发布权重、滤波后状态和前后时间，逐条独立重建递推与配额，
并与原50ms观测计数/权重和/末值交叉验证。固定内存上限4×200000×192=153.6MB，
热路径不写文件。测量结束再分析绘图，测量时不编译或做重分析。

沿用O的5pp滞回/10pp跨度/50秒至少10完整往返/五个10秒块至少四块各3往返；
3/3才称持续复现，1/10pp阈值敏感性另报。权重、逐请求分片和250ms份额分开。
曲线固定重复2、全程0–60秒（0.5秒min/max/mean）及10–12秒原始点、共用纵轴。
原始计算权重与实际采用权重均展示；不改变阈值或挑重复获得更漂亮曲线。

记录完成吞吐、端到端P99、吞吐/P99窗口CV、分配调用开销、失败/未完成数。
20%档位每秒样本可能不足500，P99窗口CV按既有规则为N/A，不降低样本门槛。
报告每重复与原算法的配对比值；吞吐≥.98且P99≤1.05仅是探索筛选，不是3次就证明
总体非劣。持续往返下降也不必然使全区间跨度下降，两者分别呈现。
本轮不做饱和容量、负载突变或断轨实测，不能据此验收原需求全部指标。
