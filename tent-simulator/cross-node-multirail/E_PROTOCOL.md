# E：学习频率与 EWMA 平滑的真实跨机对照

本轮只检验权重反馈与实际传输表现的关系，不修改生产选路实现，不注入故障。
所有执行在 SSH 内的 mooncake Conda 环境；原始数据、构建、报告全部放在
`/root/mooncake-tent-multirdma-output/cross-node-multirail/` 下的新目录。
旧 A/B/C 数据及 manifest 不覆盖，不把本轮当作旧基线的额外重复。

## 固定条件和处理变量

- 发送 A10：erdma_0 + erdma_1；接收 erdma_test：erdma_0。
- 双方默认 6 lanes；NUMA0；1 MiB/request、总 Q128、1 caller。
- 原生 C API 和 stream_native.so 不变；保持 topology、jitter、带宽上下限不变。
- 原参数：`new = alpha * old + (1-alpha) * observed`，alpha=0.01。
- 实验库仅在带宽学习前增加一个 gate：按“完成线程 × NIC”计数，每 K 个
  原本有效的反馈学习一次；K=1/10/100。先释放 inflight，再决定是否学习。
  这不是固定毫秒采样，也不是全局每 K 个反馈。未入选反馈不改变 EWMA。
- 平滑单因素：K=1，alpha=0.5/0.9/0.99；学习频率单因素：alpha=0.01，K=10/100。
- 原始 V2 与实验 K1/alpha0.01 都保留；实验库没有 QP、endpoint、故障或 Worker hook。

## 执行顺序

1. 恢复默认接收服务，执行3次10秒双轨饱和控制，检查数据、排空、两 Rail
   参与及原始库指纹。其吞吐中位数只作本轮参考容量，不称为硬件峰值。
2. 服务器构建与 gate 结构测试通过后，原始 V2 和实验 K1 做5组成对开销控制；
   每次60秒、预热5秒，组内 AB/BA 交替。使用相同的 stream/observer 设置。
3. 稳态：六种参数（K1原alpha、K10、K100、alpha0.5/0.9/0.99）分别在90%参考输入
   与饱和闭环下执行，每种每场景5次；固定种子在每个重复块内打乱顺序。
4. 稳态审计后按预先规则选择最多两个候选，与K1对照进行负载阶跃、脉冲测试，
   每种每场景5次。若没有候选满足吞吐和P99门槛，选表现最好的一个作诊断，
   明确不称为优化成功，避免只报告“获胜者”。动态数据独立于选择候选的数据。

正式稳态60秒，P99窗口固定1秒，窗口至少500个成功请求且至少20个有效窗口；
不足时窗口P99波动为N/A。额外报告全局P99。开销控制也采用同一口径。
恢复短测不报告窗口P99稳定性。所有发送完成后再分析，不与实测并发编译/分析。

## 指标、门槛及结论边界

- 吞吐：测量时间内成功完成字节/时间；报告配对比值、组中位数及配对重采样95%区间。
- P99：计划到达至完成的延迟，并拆分提交前排队与提交后耗时。
- 波动：250ms吞吐CV、1s有效窗口P99的CV、250ms分配份额标准差。
- 权重：实际用于选择的归一化权重TV、超过0.1个百分点的变化次数/秒和
  每一万次比较的变化次数；单列真实学习更新数、跳过数和各Rail实际下限命中率。
- 不能把weight comparison、请求间换Rail或retry事件直接叫作同一请求的迁移次数。
  当前无完整跨Rail请求身份，真实迁移次数保持未测。
- 候选筛选：两种稳态场景配对吞吐中位比均>=0.98、P99中位比均<=1.05；
  至少一个性能波动指标降低20%，另一项可测性能波动不增超过10%。
  仅用于选择下一阶段，不构成统计显著或最终达标。
- 声称“吞吐不下降”需配对95%区间下界>=0.98；五次不足以精确判定时写明未证实。
- 若K1实验控制相对V2的吞吐中位比<0.95，先停止参数矩阵并诊断开销。
  没有达到该停止门槛也不意味着已经证明开销<=2%。
- 阶跃20%→80%→20%，每段20秒；吞吐连续5个250ms窗口落入目标±10%为一次
  恢复确认，仍报告确认后再次出带比例。份额目标若自身不稳定则联合收敛为N/A。
- 脉冲：20秒20%负载后，20轮100ms的120%脉冲与1.9秒20%基底；按每个
  脉冲请求群检查下一脉冲前是否完成，不用全程CV冒充稳态震荡。
- 任意失败、提前停流、校验失败、observer丢失及未排空都保留并停止调查；
  不自动重试、不剔除失败。有限deadline/进程watchdog不能当作所有故障场景无挂起的证明。

改变K带来的更新次数变化具有机械性；实验成功必须体现在实际传输表现上。
报告须区分：真实实测、结构校验、因果证据不足及尚未覆盖的场景。

## 正式运行前的协议修订（v2）

首次K100短测使用2秒P99窗口；原汇总器只允许250/1000/5000ms，传输完成后
汇总报错，套件保留failed，不能当作已通过的性能样本。正式矩阵尚未开始。
为保持原汇总器源码和指纹不变，改用受支持的1秒窗口，并保留上述样本门槛。
首次短测未通过numactl固定亲和性，仅作兼容性诊断；后续短测和正式运行均固定NUMA0。

## 报告阶段的运行时边界澄清

90项正式运行的原始release_bounds/candidate记录已逐行审计：erdma_0的理论带宽、
下限、上限为100/10/1000Gbps，erdma_1为10/1/100Gbps；NUMA惩罚分别为1和10。
原始V2与实验库一致。400/40Gbps是未知速率时的回退配置，并非这些运行的实际边界。
原文“40Gbps下限命中率”是解释文字错误；指标程序一直使用实际new_equals_min标记，
没有硬编码40，候选筛选规则和任何测量数据均未改变。原协议及指纹保留在本轮
仓库外source-snapshot/与source-sha256.json中。以上算法输入不等于物理链路容量。
