# RB：速率估计与整批分配的交叉消融

## 正式阶段v2修订：边界修复与独立旧库对照

正式v1首个样本14,619个已接收请求全部成功、pending0、正确性通过、observer完整，但流量器
把一个数学上位于结束边界的额外到达因double速率/long double计算识别为end−1ns，导致
scheduled_arrivals_unaccepted_at_end、rejected1、RC1。失败样本/计划/日志/冻结源全部保留。
不修改流量器，也不放宽成功判据；v2把正输入统一量化为最近的整数requests/s，所有策略
相同：20%名义档225rps=1.8874368Gbps，60%名义档675rps=5.6623104Gbps，相对原计划
均约增加0.0445%。实际比例随case记录，不再声称输入恰好是参考的20%/60%。
先用与native相同的offset表达式做C++边界回归，验证最后合法到达和第一个区间外到达。

开销对照吞吐配对比1.16484/.96573/.97321，通过预设.95门槛；但P99比1.14236/1.22217/1.29204
全部偏高，不能忽略。因此正式v2增加旧O观测库的reference原算法作为第七组；原original组
表示“原算法＋新计数”。最终同时报告相对reference的整套方案代价和相对original的算法差异。
v2为7×2×3=42个正式点。复用已完成的标定、功能检查与饱和开销对照，库和算法不改；
所有修订发生在有效正式矩阵启动前，首个失败样本不删、不静默替换。

2026-09-29。用户已授权在调研后继续实现与实测。所有执行只在 SSH 的 mooncake 环境，
本地仅编辑/传输源和静态报告。复用每台主机一个会话，完成后关闭，不使用scp。
数据、构建、图和报告置于仓库外；既有O/CAND/E输出不覆盖。

## 先标定，再冻结输入

同一A10双eRDMA→erdma_test单eRDMA，发送NUMA0、双方6lanes。
沿用Host内存1MiB请求、16×64KiB Slice、Q128、单caller、每API batch一个request。
先用原V2观测库对S0/S1/D0各做3次12秒饱和短标定（3秒预热），数据校验后取中位。
单轨完成吞吐是当前环境服务能力参考，不是物理峰值保证；D0同时揭示共享接收瓶颈。
正式固定输入采用当日D0参考的20%/60%；与9/17参考不同则明确报告，不冒充完全相同输入。

## 交叉矩阵

| 策略 | 用于评分的速率 | 配额 |
| --- | --- | --- |
| reference（v2） | 原单Slice延迟EWMA、原NUMA项，旧O观测库 | 原取整 |
| original | 原单Slice延迟EWMA、原NUMA项 | 原取整 |
| legacy-remainder | 同original | 最大余数 |
| fixed-remainder | 单轨标定服务速率固定 | 逆评分＋最大余数 |
| aggregate-remainder | 以标定为初值的区间完成速率估计 | 逆评分＋最大余数 |
| fixed-batch | 与fixed-remainder完全相同的固定速率 | 整批预计完成时间最小化 |
| aggregate-batch | 与aggregate-remainder相同估计器 | 整批预计完成时间最小化 |

新固定/聚合速率是NUMA0下相应真实内存路径的有效服务速率，已包含该路径代价，因此
这四组不重复乘原来的NUMA1/10惩罚。原两组保持原参数。四组内部交叉用于分因素归因；
original→fixed同时涉及标定/先验归一化，不能称只删除EWMA这一项。所有组保留原jitter和
每100次probe，probe权重仍是诊断量；批量门槛不修改，必须核验实际进入16片双轨路径。

初版批量模型T_i=(Q_i+x_i)/C_i，基础延迟L暂设0，Q使用捕获的inflight作为代理。
双轨连续解x0=(C0*M+C0*Q1−C1*Q0)/(C0+C1)，截断到[0,M]，再比较相邻整数份额
及两个单轨端点的最晚完成时间。只对分到数据的轨计请求完成时间，平局按固定规则。
不新增逐Slice债务调度循环；不让请求等待控制周期。共享接收瓶颈、inflight代理与L=0
的局限须在结论中保留，不能据此宣称模型已准确。批量方案的目标份额来自连续完成时间解，
整数份额独立核验；候选评分仍记录原jitter，但批量求解不使用随机抖动做决策。

## 聚合估计器约束

以成功完成的字节增量和对齐时间区间为信号，采样不在单个Slice完成时直接替换带宽。
必须保留CQ聚集、发送时间跨度、持续在途工作量、无效完成/重试及样本不足的审计信息；
不把“没有足够待发工作”得到的低吞吐当作容量下降。实现的确切窗口、更新增益和有效性
规则在功能检查前冻结，不根据正式结果调参。若门控导致没有有效学习，要如实报告
未激活，不能把固定初值的结果冒充自适应能力。

本版规则：单caller在每轨至少间隔5ms时读取跨worker聚合的成功完成字节计数；分母取
观测间隔与最新成功完成Slice的submit时间跨度两者较大值。需本区间至少256KiB成功完成，
且整个区间记录到的最小已post未完成字节>=128KiB，没有无效完成，才更新；否则保留估计。
更新增益dt/(20ms+dt)，有效样本限制到单轨参考的[0.05,2]倍。其余样本仍导出作审计。
这是一版有界的区间完成速率原型，不是完整BBR采样器；持续在途阈值只是负载充足的代理，
不能声称精确识别了所有application-limited情况。窗口内多个原子计数读取不是硬件同一时刻
快照，发送跨度也来自成功完成集合的最新时间，局限需在分析中保留。低输入下不更新是允许
结果；真容量下降/恢复速度和更一般的样本识别不在本轮固定输入测试中得到证明。

## 阶段与验收

1. 环境/标定；结构测试覆盖容量退化、无效样本和空闲、以及批量解对穷举整数最优的等价性。
2. 每策略短pilot，核验真实权重、整数配额、速率状态及正确性；另做旧O库与RB原算法
   的3对短饱和观测影响对照，再冻结正式矩阵。若新增观测使吞吐配对中位低于0.95则停止调查。
3. v2七组×两输入×三重复，每次60秒＋5秒预热，分析第10–60秒；保留同轮旧O库与新计数原算法对照。
4. 使用O/CAND相同权重跨度、5pp往返、250ms份额、吞吐与P99口径；明确连续目标权重与
   实际整数配额，不能通过把权重换名为容量占比制造“稳定”。图固定重复2及10–12秒窗口。
5. 比较每重复P99与分配调用开销，不仅报告中位数；失败/未完成不丢弃、不静默重跑。

只有前述交叉对照表现支持，才值得再引入按预计收益触发的稳定机制。若仍明显退化或
估计器未激活，先给出限制与原因，避免叠加机制掩盖问题；不将本轮称为完整故障/动态验收。
