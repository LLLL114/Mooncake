# 多轨 RDMA：指标合同、原算法 baseline 与后续方案准入

日期：2026-09-09。实施顺序：**先冻结指标 → 原算法基准测试 → 解释基准与缺口 → 再实现候选方案**。
本轮不实现新调度算法，不修改 TENT 生产默认路径。

## 1. 冻结对象和证据范围

- A10 `/root/mooncake`，分支 `experiment/rdma-multirail-baseline`。
- 本轮开始提交 `7ee9e26cc5dab6aff0d164af634e77021d521cf2`；原生产算法基线 `1c65ced88e509440e31ea88a76594660461d0eab`。
- 新文件限于 `tent-simulator/acceptance/`；结果在该实验目录的 `/root/mooncake-tent-multirdma-output/runs/acceptance-baseline/`，禁止覆盖旧 A–F / candidates 数据。
- 原算法：smart=true、alpha=.01、原 NUMA 因子、原 jitter、原 floor+余数给最优、原每百次批量 RR 探测。保留生产 Slice 切分和批量门槛。
- S 层：真实 DeviceSelector + 可控服务模型。用来归因、注入参数和容量变化，不代表真实网络性能。
- R 层：同机两 eRDMA，真实 RDMA-CM/WRITE/CQ + 原 DeviceSelector，CPU 内存、单生产线程。它不是完整 TENT Worker/endpoint，也不是跨节点网络。
- T 层：完整 TENT 多 Worker、多 peer、跨节点、Rail 故障和恢复。当前会话无第二节点，现有驱动也没有生产重试状态机，此层未测指标一律 N/A，不能用零替代。
- 机器有 8 张 A10 GPU 不等于 8 条 Rail；本轮 CPU WRITE 基准只涉及两张 eRDMA。

## 2. 原始观测与共同统计规则

每次决策观察候选逆评分归一化值 p；每请求保留计划到达、实际进入分配、完成时刻、整个请求分配耗时、第一轮 p、实际 Rail 字节份额。按实际 CQ 完成时间累计各 Rail 完成字节。线上循环只记数/写预分配数组，排序和 JSON 输出放在测量结束后。

原算法的 p 是即时计算值，没有独立的“持久权重发布”动作。分别报告：①计算权重变化；②未来候选策略的持久目标发布；③实际字节分配变化。单片 argmin 和周期 RR 不按 p 做比例分配，仍保留标签，不把 p 当成实际路由概率。

- 实机每场景 5 次独立进程重复，固定种子 `[1,2,19,12345,4294967295]`，随机化场景顺序；种子不能控制 OS/网络噪声。
- 正式测量 1 s 预热 + 10 s 测量，固定到达负载与饱和闭环分别测试。请求量/到达间隔和实际持续时间全部落盘。
- 主窗口 250 ms（每次至少 40 个完整测量窗口），50 ms / 1 s 为敏感性分析。窗口不因算法改变。
- 吞吐窗口按完成时刻分桶；P99 窗口按计划到达时刻分桶，等待这些请求全部终结后计算，避免漏掉跨窗慢请求。
- P99 使用 nearest-rank；每个窗口至少 500 请求，否则该窗口 P99 为 N/A，披露有效覆盖率。500 仍只有约 5 个尾部样本，不能把单窗 P99 当精确总体参数。
- 窗口波动计算 population SD/mean（CV），同时给 SD、P95-P5 和 mean，避免均值下降造成 CV 虚高。
- 使用运行级中位数、范围和置信区间；不把相关请求当独立重复。5 次的区间只作初步估计，靠近验收边界时扩展到至少 10 次。
- 仿真保持 ns 时间戳；其短动态场景另用固定 1/10 ms 窗口，不与实机 250 ms 的波动数字直接比较。

## 3. 指标的精确定义

记 R 为可用 Rail 数，T 为测量时长，p_i 为归一化权重，a_i 为一个请求的实际字节份额，x_i(k) 为窗口完成字节/s，C_i 为相同条件下单 Rail 标定的可达吞吐。

| 用户指标 | 主指标与计算 | 补充指标/解释 |
|---|---|---|
| 吞吐不下降 | 饱和有效完成字节/T；固定负载另报完成速率/输入速率 | Gbit/s、请求/s、最大注入迟到、积压。固定注入跟得上不能证明吞吐上限不降 |
| 权重变化频率 | 相邻决策 TV=0.5Σ|p_i(t)-p_i(t-1)|；count(TV>δ)/T | δ=0.001（0.1pp）为主，1e-6/0.01 为敏感性；并报每万次决策次数、TV/s、平均步长。未来发布次数单列 |
| 权重反复调整 | 两 Rail 下，超过 δ 的有符号变化发生方向反转的次数/T | 只在各稳定阶段内统计，跳过小变化；不跨预热和阶段边界比较。不称为数学失稳证明 |
| 分配震荡 | 相邻请求 a 的 TV；固定窗口分配字节份额的 SD、TV/s、P95-P5 | 单片 0/1 交替可能正常；窗口份额为主，相邻请求变化为诊断 |
| 流量迁移 | 同一逻辑流后续未提交字节的改派次数/流与改派字节占比 | 当前独立请求驱动无稳定流标识，此指标 N/A；首 Slice 换路只作诊断 |
| 故障重试迁移 | 每万请求重试次数、跨 Rail 重试次数、重发字节/有效字节 | 正常驱动没有重试实现，不能报告“迁移为 0，已达标” |
| 吞吐波动 | 固定窗口 G(k)=Σx_i(k) 的 CV、SD、P95-P5 | 稳态分别统计，负载阶跃本身不能当震荡 |
| P99 波动 | 同一固定到达窗口内请求 P99 的 CV、SD、P95-P5 | 整体 P50/P99/P99.9、deadline 超时率；不要把整体 P99 下降等同波动下降 |
| 多 Rail 利用率 | u_i=x_i/C_i；Σx_i / 同条件双 Rail 饱和标定 | 各 Rail 单独报告。C_i 不使用原算法不稳定的 EWMA，也不把 100G 标称当可达能力；共享瓶颈下 ΣC_i 不等于双 Rail 容量 |
| 负载均衡 | 每窗归一化利用率 Jain=(Σu_i)^2/(RΣu_i²)；|u_0-u_1|/(u_0+u_1) | 同时报全局值和窗口分布；异构链路不要求字节 50/50，低负载允许合理 NUMA 偏好 |
| 分配成本 | 每请求全部 allocate 调用墙钟时间的均值/P99/P99.9 | 分清请求与 API 调用，512KiB 可能调用 8 次；含调度的端到端时延是主要业务约束 |
| 收敛 | 扰动后首次进入目标带且连续保持 H 的时间；再报直到阶段结束是否重新出带 | 仿真份额带 ±5pp、吞吐误差 ≤5%，H=100ms；不满足给右删失，不填 0；持续低负载时参考带不能盲用容量比例 |
| 持续震荡 | 稳态连续子区间的份额幅度与反转是否衰减，并看队列、吞吐和 P99 是否同步受损 | 有界周期变化与队列发散分开；有限时长测试不能证明永远稳定 |
| 不永久挂起 | 每个接收请求必须在声明的 deadline + 有限重试预算内进入唯一成功/失败终态 | accepted=success+failure+pending，结束 pending=0，资源计数归零；正常完成测试只覆盖正常路径 |

## 4. 本轮原算法测试矩阵

### R：新增同机真实 RDMA 基准

1. 每张 Rail、双 Rail 的 RR 饱和标定，记录设备、固定应用 QP/slot 预算，不修改物理网卡状态。
实际 NUMA 内存分配未绑定；“双 NUMA”指选择器评分拓扑，不代表源内存已经按该 NUMA 对照放置。

2. 双 Rail 等亲和：64KiB/1MiB × 20%/60%/90% 标定负载；双 NUMA 评分：1MiB × 同负载。
3. 饱和：等亲和 64KiB/512KiB/1MiB，以及双 NUMA 1MiB；单 Rail 1MiB 分别饱和。每组 5 次。
4. 分配门槛验证：512KiB/960KiB 走单片调用，976KiB 含尾片走批量；真实基准仅 full-slice 大小，尾片先在 S 层验证并披露限制。
5. 新增权重变化计数开/关短配对运行，其余时间戳、完成字节和请求记录保留，评估该部分采集扰动；不从测量值中扣掉开销，也不宣称测出了全部插桩相对裸 TENT 的开销。
6. 记录每次 CQ 身份和完成字节守恒、最终写入槽校验及 inflight 排空。它们不构成每次覆盖数据的独立 CRC 检查，也不构成生产故障验收。

### S：重新生成原算法轨迹

本轮检查时旧运行目录保留日志，但没有找到可直接复算的旧 JSON 轨迹。因此重新运行原算法模型，采用 3 个固定种子 `[1,19,12345]`，并做确定性轨迹等价性验证；旧报告仅作历史背景，不填入本轮基准表。

- 稳态、门槛、尾片；采样/alpha/CQ 周期与调度反馈关系。
- 负载阶跃/短突发、单 Rail 100G→50G→100G；区分剩余容量足够和输入过载。
- 多线程同步到达与错峰；固定总输入和资源预算，不能通过增加 Worker 同时增加总容量。
- 降容不是 Rail 故障；仿真不自动包含真实 QP 错误、生产重试和超时状态机。

### T：未具备的完整故障基线

后续需在独立测试连接上注入：post 前故障、已 post 未 CQ 的 QP 故障、错误 CQ、单 Rail 持续不可用、恢复抖动、全 Rail 不可用。禁止直接关闭当前 SSH 所用物理网络。分别记录故障注入→检测→最后错误新分配→首个健康路径完成、恢复份额及所有请求终态。现有 baseline 报告保留缺口，不以模拟降带宽替代。

## 5. 后续候选准入（建议门槛，尚不是用户已确认的 SLO）

基准跑完后才实现“原算法最小修改”和“稳定份额+批量配额”。所有候选复用同一测量工具、窗口、负载、资源预算和种子，不在每个场景单独调参。

- 吞吐：同时报告相对差和配对区间。建议以 -1% 非劣界做统计筛查，但这不是把用户的“不下降”改成允许下降；若要求严格 0% 界，按该界判断，区间跨界判证据不足。
- 稳定性：在 baseline 确有问题且非接近零的场景，建议权重变化事件/TV、窗口分配份额 SD 至少降低 50%，吞吐/P99 窗口 SD 至少降低 20%，且 CV 不发生显著恶化。两类统计同时披露。
- 均衡：改善按容量归一化的窗口不均衡，且不能通过牺牲吞吐和低负载时延强求均分；baseline 已接近 Jain=1 的场景以不退化为主。
- 时延：各正式场景端到端 P99 不退化，重点单列小请求/低负载；分配均值和尾部另设预算，不能用高负载收益掩盖小请求回退。
- 突变：同时检查恢复速度、超调、重新出带次数和积压排空；负载超过剩余容量时不要求队列不增长。
- 故障：有限 deadline 内全部终结，记账守恒；正常场景性能达标不豁免此项。
- 所有“显著”结论以独立运行重复为单位；baseline 为零或 N/A 的指标不能计算虚假的百分比改善。
