# TENT 多轨 RDMA 现有算法基线与归因实验方案

> 状态：P0/P1 与实验 A/B/C 的 CPU 仿真已完成；真实 RDMA 性能验证待开展。其余实验的预期关系仍待验证。
> 编写日期：2026-09-08。实验环境：A10 服务器的 `/root/mooncake`，独立实验分支。
> 分支：`experiment/rdma-multirail-baseline`。基线：`1c65ced88e509440e31ea88a76594660461d0eab`。

## 1. 目标、范围与完成条件

建立现有多轨 RDMA 算法基线，复现并量化权重震荡、流量份额摆动、负载失衡、频繁选路切换和请求尾时延波动，分析它们与估计更新周期、EWMA 增益、批量分配和局部决策的关系。

本阶段不实现替代选路算法。固定周期更新、冻结带宽、关闭探测等仅作为独立的诊断干预，默认关闭。必须保留未经算法修改的基线运行方式，不得将干预结果描述为生产优化收益。

完成条件：

1. 固定代码版本、运行配置、拓扑、负载和随机种子，得到可复跑的原始基线。
2. 对每类问题提供最小复现；未出现的问题明确写“在已测条件下未复现”。
3. 用单因素干预验证或否定假设，报告效果量、置信区间与适用范围。
4. 区分仿真、同机 RDMA 与跨节点结果，不互相替代。
5. 无损坏数据、重复终态或永久挂起；失败和超时不能从性能结果中隐去。

## 3. 需要固定的算法事实

此前分析的 A10 基线为 `1c65ced88e509440e31ea88a76594660461d0eab`，正式实现前对照文末实际分支起点复核差异。

相关源码位于 `mooncake-transfer-engine/tent/`：

- `src/transport/rdma/quota.cpp`：`DeviceSelector` 候选构造、选路、批量分配与 EWMA。
- `src/transport/rdma/rdma_transport.cpp`：请求切片、批量分配阈值。
- `src/transport/rdma/workers.cpp`：逐 Slice 选路、远端映射、post/CQ、重试和超时。
- `src/transport/rdma/rail_monitor.cpp`：端到端 NIC 映射和故障隔离。
- `include/tent/transport/rdma/quota.h`：调度参数和统计结构。

现有本地 NIC 分数与派生权重：

```text
score_i = ((inflight_bytes_i + slice_bytes) / ewma_bandwidth_i)
          * numa_penalty_i + jitter
weight_i = 1 / (score_i + epsilon)
p_i = weight_i / sum(weight)
```

成功 Slice 以本次 post 到 CQ poll 的时长产生完成速率样本：

```text
B_sample = slice_bytes / attempt_post_to_completion_seconds
B_new = alpha * B_old + (1 - alpha) * B_sample
```

默认 `alpha=0.01`，即新样本权重 99%，旧值权重 1%。该值是逐成功完成事件更新，不是固定时间采样。批量分配按比例向下取整，余数全部给当前最优 NIC；每第 100 次多 Slice 分配进入轮询探测。达到 `max_slice_count/2` 才预先批量分配，其余由 Worker 逐片选择；实际阈值必须根据操作类型、内存类型、切片与尾片处理确认。

“Rail 权重”在本方案中特指上述本地 NIC 派生份额，端到端 `(local_nic, remote_nic)` 映射另行记录，不混作同一层。QoS 候选过滤、优先级轮转、共享配额、故障和 GPU 可达性过滤均需记录或作为独立控制变量。

## 4. 三种时间尺度与观测设计

| 时间尺度 | 当前行为 | 实验意义 |
|---|---|---|
| 观测周期 `Delta_obs` | 指标导出与分析窗口 | 只影响看见的曲线，不改变调度 |
| 估计更新周期 `Delta_u` | 默认每个成功 Slice 完成时更新 | 随完成事件率、CQ 批量改变 |
| 决策周期 | 请求批量或 Worker 逐 Slice 选择 | 决定快照陈旧性与一次分配规模 |

优先级轮转和每百次多片分配探测另外标记。不得将调大日志窗口后曲线变平解释为算法稳定性改善。

### 4.1 事件链与字段

```text
request arrival -> slice allocation -> worker queue -> post WR -> CQ completion
                                              -> failure -> retry -> terminal
```

记录 request/slice/attempt ID、长度、操作、源/目标内存位置、优先级、进程、Worker、QP、本地/远端 NIC、候选集合、分配理由、原始样本、EWMA、score、权重、在途量、posted 量、QP 占用、时间戳、重试、超时与最终结果。

计时使用单机单调时钟；跨节点不得直接相减未经校准的时间戳。请求端到端时延从预定到达时刻及实际提交时刻分别统计，防止负载生成器滞后被隐藏。记录 CQ poll 间隔和每次 poll 完成数。

使用线程本地缓冲与异步落盘，禁止逐 Slice 同步日志。记录观测丢弃计数；事件缺失的运行不得作为精确时序归因证据。以开/关观测配对运行测开销，目标约 1%，不满足时保留完整聚合计数、降低详细事件采样。

### 4.2 权重可比性

同时保留真实决策权重与固定参考请求的影子权重。影子请求固定大小、位置、优先级和候选集合，只计算不分配、不更改计数、不推进生产随机数状态。故障或资格变化单独标记。影子快照需要包含状态版本或时间，以识别并发非一致读取。

按 peer、源/目标位置、操作、大小区间、优先级分组，避免把业务构成变化当成权重震荡。同步记录分配份额与完成份额，二者不可互换。

## 5. 指标及判定口径

设固定分析窗口下的归一化权重为 `p_i[k]`，分配字节份额为 `f_i[k]`，总时长为 `T`：

```text
weight_TV_per_second = sum_k(0.5 * sum_i(abs(p_i[k] - p_i[k-1]))) / T
traffic_TV_per_second = sum_k(0.5 * sum_i(abs(f_i[k] - f_i[k-1]))) / T
```

所有比较固定窗口宽度和业务分组。无流量窗口不强制填零份额；标记为空闲，并单独报告。

| 问题 | 主指标 | 辅助判据 |
|---|---|---|
| 权重震荡 | 权重 TV/s、标准差 | 自相关、频谱、往返幅度 |
| 流量摆动 | 分配份额 TV/s | 分配与完成份额的时滞 |
| 负载失衡 | 归一化利用率 CV、Jain 指数 | 队列字节、排空时间差、总吞吐 |
| 切换频繁 | 类别内首选路径切换/万次决策 | 停留时间、每 GiB 切换率 |
| 实际改派 | 已分配未 post Slice 换路数 | 不存在此行为则为 0 |
| 故障迁移 | 重试换路次数与字节 | 单独列出，不混入正常切换 |
| 尾时延 | 请求级 P50/P95/P99 | 分窗 P99 波动、超时/失败率 |
| 系统代价 | 去重有效完成吞吐、CPU 成本 | 重试流量、观测开销 |

正常 Slice 喷洒不是迁移；没有持续 flow 时仅报告“类别内首选路径切换”，不称连接迁移。累计分配量包含尝试流量，不能当作有效吞吐。

异构路径使用 `u_i = measured_goodput_i / calibrated_effective_capacity_i`，Jain 指数为 `(sum u_i)^2 / (n * sum u_i^2)`。总利用率为零时指数不定义。容量从独立标定获得，不能拿被评估算法的动态 EWMA 做分母；共享瓶颈不得简单相加。低负载下无需强求每条 Rail 都忙，均衡结论主要针对可饱和且允许利用多路径的场景。

不同运行中分窗 P99 需具有足够样本；样本稀少则扩大窗口或只报告整段分位数，不计算误导性的“P99 CV”。超时可能右删失，必须另外报告比例与请求期限，不仅统计成功请求。

## 6. 基线组与共同运行规则

| 组 | 定义 | 用途 |
|---|---|---|
| B0 | 原始 smart 配置、仅观测插桩 | 主要基线 |
| B1 | 同 commit 关闭 smart | 稳定策略参照；可能只使用首个可用拓扑层级 |
| B2 | 同 B0，仅改变 alpha | 估计器增益归因 |
| D-* | 同 B0，仅打开一个诊断干预 | 不作为生产性能结论 |

B0 先保留真实默认 QoS 等配置，然后增加关闭优先级过滤的独立对照，不能悄悄把它从基线拿掉。B1 候选范围可能不同，不能将全部差异归因到 EWMA。

使用开环预定到达序列测排队与尾时延，闭环另测饱和吞吐。比较不同 Worker/进程时固定总 offered load；比较更新频率时记录并控制请求/完成事件率。初始负载为标定容量的 20%、60%、90%、110%。过载实验设有限时长、最大在途量及请求期限，报告达到限额后的拒绝/积压；不得通过只保留成功请求美化结果。

真实环境每组预热 30–60 秒，稳态采集 3–5 分钟，至少 5 次配对重复；仿真固定种子并重复多组种子。算法运行顺序随机化，使用相同到达轨迹配对。置信区间采用运行级或时间块 bootstrap，不把强相关 Slice 当独立样本。阶跃另设稳定前段、扰动段、恢复段，各段至少覆盖数倍待测时间常数。

## 7. 实验矩阵与预期关系

### A. 原始稳态：恒定外部条件下是否自发震荡

- 两条等容量 Rail，固定拓扑、固定大小，先单 Worker/进程。
- B0/B1，负载 20%、60%、90%、110%；请求 64 KiB、512 KiB、1 MiB、16 MiB。
- 分别在相同亲和层级的合成拓扑、A10 实际双 NUMA 拓扑验证。
- 输出权重/份额/队列/吞吐/P99 同轴时间线。

预期：低负载可能只有选路抖动；接近饱和时误判更容易变成排队差与 P99 波动。过载时吞吐可能保持饱和而队列恶化，不预设“越高负载，吞吐越震荡”。若 B0 不震荡，则保留此负例再引入下一组扰动。

### B. EWMA 灵敏度：增益是否过高

- `alpha = 0.01, 0.5, 0.9, 0.99, 0.999`，其余固定。
- 先单独喂入恒定均值加独立噪声，确认公式、上下限裁剪、更新顺序。
- 再回到完整闭环，分别输入短期噪声和真实持续降速。

独立同分布输入、无裁剪的理论关系：

```text
Var(B_ewma) / Var(B_sample) = (1 - alpha) / (1 + alpha)
alpha=0.01 -> 98.0%; 0.5 -> 33.3%; 0.9 -> 5.3%; 0.99 -> 0.5%
```

预期：alpha 增大使样本噪声传播下降，但真实变化响应变慢。该方差公式仅是估计器校验，不能直接预测闭环 P99。若估计变平但份额仍往返，则转查批量分配、QoS 候选变化和局部决策。

### C. 更新周期和 CQ：固定参数为何随事件率变化

1. 保持逐完成更新，改变 CQ poll 间隔与批量，固定负载和服务能力；采用仿真完成事件合批优先隔离变量。
2. 诊断版本将更新节流到 `Delta_u = 0.1, 1, 5, 10 ms`，保持原样本口径，不同时改成新带宽估计器。明确固定窗口代表样本的选取规则并记录跳过数。
3. 分别用固定 alpha 和固定时间常数 `alpha=exp(-Delta_u/tau)` 对比；`tau` 从 20、50、100 ms 筛选。
4. 从细粒度事件聚合 1、10、100 ms 观测窗口，检查混叠。

原始逐事件更新在稳定完成事件率 `r` 下，其旧信息衰减的时间常数近似为 `tau_eff = -1 / (r * ln(alpha))`。事件率不同，同一 alpha 的墙钟记忆不同；实际 r 受选路影响，此式不能当作完整闭环模型。

预期：固定 alpha 时降低更新频率通常更平稳但更慢；固定 tau 后差异应缩小。CQ 合批使样本集中更新，可能增强批内顺序影响。若只是日志窗口改变就得到不同震荡结论，应先排查观测混叠。

### D. 批量分配与探测：微小差异是否被离散化放大

> 2026-09-08已完成。根据A/B/C增加冻结带宽、相同贪心规则下的批内快照对照，并统一逐请求首轮权重与物理字节份额口径。详细调整见[instrumentation/experiment-d.md](instrumentation/experiment-d.md)，结果见[实验D报告](/root/mooncake-tent-multirdma-output/reports/experiment-d-report.md)。分配干预仅用于诊断，不替换生产算法。

- 覆盖实际批量阈值前后、不同 Slice 数、两条/多条候选、尾片和非尾片。
- 通过真实分配函数测试接近相等的候选分数；同时记录输入权重与输出字节份额。
- 单独标记第 99、100、101 次多片分配；用固定大小和混合大小请求比较探测流量。
- 诊断开关分别仅改变余数处理或仅关闭探测，不能同时改变。

确定性例子：16 片下，49%/51% 向下取整再将余数给最优路径，得到 7/9；51%/49% 得到 9/7。权重移动 2 个百分点，分配份额移动 12.5 个百分点。

预期：Slice 数相对候选数较少时取整影响更强；最优路径反复换位时余数归属放大份额跳变。每百次探测可能制造与调用次数相关的扰动，混合请求大小下不等于固定 1% 字节探测量。是否进一步损害 P99 取决于提交与队列反馈，需闭环验证。

### E. 局部决策：是否同时涌向同一条 Rail

> 已完成。调整后的精确定义及复现见[instrumentation/experiment-ef.md](instrumentation/experiment-ef.md)，结果见[总体总结](/root/mooncake-tent-multirdma-output/reports/rdma-multirail-baseline-summary.md)。

- Worker 数 1、2、4、8；进程数 1、2、4；同步突发与错峰到达。
- 固定总 offered load、请求大小分布、拓扑和总 QP/队列资源预算，无法保持一致的资源项单独披露。
- 记录读取状态、选路和预占记账的时间及并发重叠。
- 诊断对照一：进程内串行化“读状态—选择—记账”；对照二：仿真多进程共享完整负载视图。

预期：同步突发、陈旧快照、跨进程不可见负载可能导致集中选路与轮流积压。串行化有效支持预占协调问题；仅共享视图有效支持跨进程可见性问题。单进程已有共享 NIC 计数，不预设 Worker 越多必然越差。串行化降低实际注入速率的运行不能直接作为稳定性收益证据。

### F. 阶跃与脉冲：稳定性和响应速度如何权衡

- 负载 30% -> 90% -> 30%。
- 独立实验中，仅将一条 Rail 有效容量 100% -> 50% -> 100%。
- 短脉冲持续 1、10、100、1000 ms，长阶跃持续到足以观察新稳态。
- 报告响应延迟、份额超调、队列峰值、恢复后往返次数、请求 P99 和收敛时间。

收敛定义：进入新稳态参考值 ±10% 区间并保持指定驻留时间，驻留时间须大于数个控制更新周期；未收敛报告为右删失，不强行给数值。新稳态由长时恒定条件标定，不能用未知最优份额直接当真值。

预期：原始高增益可能对短脉冲反应过度，扰动结束后继续追赶旧信号；更强平滑可降低短脉冲引发的摆动，但持续降速时延迟卸载并增大积压。最终应给出稳态变差—突变收敛/P99 的权衡曲线，而非只选一张平滑曲线。

## 8. 仿真、回放和实机的证据边界

仿真须驱动该分支真实 `DeviceSelector` 分配/完成接口，采用可注入时钟和确定性种子；不得只重新抄写一份近似算法。若时钟或随机数不可控，先做最小隔离改造并验证与原始接口一致。模型包含 NIC 服务、共享瓶颈、QP 排队、CQ 合批及软件排队，确保每个排队阶段只计一次。

先用无噪声单 Rail、等容量双 Rail、字节守恒、尾片、完成/失败释放和确定性取整案例校验仿真，再研究闭环。FakeTransport 只证明 runtime 终态与回退，不替代 RDMA 调度或 DMA 测试。

回放固定请求到达、大小、位置、优先级和外部干扰。换策略后必须重新生成队列与完成事件；不能把旧策略的 completion 时间作为新策略的真实结果。静态日志回放只能分析决策差异，性能预测需经实机标定。

同机实验先显式限制 RDMA，确认真实 backend、NIC/端点及完成计数，排除 SHM/CUDA IPC/其他本地传输接管。先逐 Rail 做短时 DRAM/GPU 数据一致性测试，确认 provider 支持本机路径后再扩展。高层延迟注入只称调度延迟，未经验证不把 `tc/netem` 视为 eRDMA 网卡数据路径拥塞。

最终跨节点先分别标定 Rail 容量和双路共享瓶颈，再重复关键最小复现；多发送方结论另做至少三节点确认。

## 9. 因果归因与结果判断

分析链条：原始样本 -> EWMA -> 权重 -> 分配份额 -> 队列 -> 请求 P99，同时保留队列反向影响样本的反馈。互相关与时滞只提供线索，因果结论依靠单因素干预及重复结果。

| 假设 | 支持证据 | 未支持时下一步 |
|---|---|---|
| 更新增益过高 | 只增大 alpha 就降低权重和份额变差 | 分配离散性、候选变化 |
| 排队压力被重复放大 | 仅冻结带宽后队列往返减少，且服务模型和负载未变 | 检查其他反馈环节 |
| 取整放大 | 仅改变余数处理，阈值附近跳变减少 | 提交与完成反馈 |
| 局部集中决策 | 固定总负载，错峰/协调后摆动下降 | CQ、QoS 等周期源 |
| 探测扰动 | 异常与探测对齐，关闭后消失 | 其他周期源 |

本阶段不预设算法优化门槛。先报告效果量、95% 置信区间、绝对吞吐/P99 和失败率；有持续周期峰、显著往返幅度且跨种子重复，才描述为持续震荡。仅一次负载阶跃的调整不是持续震荡；平滑但吞吐下降的干预不能称改善。
